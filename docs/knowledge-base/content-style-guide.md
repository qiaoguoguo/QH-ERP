# 系统操作知识库内容写作规范

## 目标

本文用于约束“全系统操作知识库”初始内容、后续维护内容和验收题集的写法。知识库只解释当前系统已经存在或已明确标注现状的页面、路由、状态、字段、按钮、错误和跨模块影响，不写通用 ERP 教程。

## 文章 JSON 字段

每篇文章必须使用以下字段：

- `slug`：稳定英文标识，发布后不得随意修改。
- `title`：用户能搜索的中文标题，优先使用页面名、按钮名或业务问题。
- `summary`：一句话说明能解决什么问题。
- `categoryCode`：必须匹配 `categories.json` 中已声明的分类编码。
- `knowledgeType`：只能使用 `PAGE`、`PROCESS`、`FIELD`、`STATUS`、`ERROR`、`PERMISSION`、`IMPORT_EXPORT`、`CONCEPT`。
- `content`：受控 Markdown 正文。
- `keywords`：逗号分隔，覆盖页面名、按钮名、字段名、状态、错误文案和常用口语。
- `routePaths`：换行分隔的规范化路由，只写路由模板，不写实际单号和查询参数。
- `pageNames`：换行分隔的页面名或弹窗/抽屉名。
- `permissionNote`：说明查看、维护、提交、审批、过账等所需权限。
- `relatedSlugs`：相关文章 `slug` 数组，可以跨文件引用，由装载器在全部文章装载后解析。
- `sortOrder`：同分类内排序。
- `status`：当前只使用 `ENABLED`。

## 分类约束

- `categories.json` 必须按父分类在前、子分类在后排列。
- 当前初始资源只提供 8 个一级分类，没有子分类，因此天然满足父分类在前。
- 文章 `categoryCode` 只能引用 `COMMON_SYSTEM`、`MASTER_MATERIAL_BOM`、`INVENTORY_QUALITY`、`PROCUREMENT`、`SALES`、`PLANNING_PRODUCTION`、`COST_FINANCE_REPORTS`、`PLATFORM_IMPORT_EXPORT`。
- 不允许文章引用未声明分类。

## 正文格式

正文只允许：

- `#` 一级标题。
- `##` 二级标题。
- 普通段落。
- `-` 无序列表。
- `1.` 有序列表。

正文禁止写 HTML、脚本、内联样式、表格控件、业务执行按钮或可被误解为系统自动操作的表达。

## 推荐正文结构

页面操作类文章建议使用：

1. `# 功能用途`
2. `# 页面入口`
3. `# 操作前提`
4. `# 操作步骤`
5. `# 关键字段和状态`
6. `# 常见错误和处理`
7. `# 上下游影响`

流程、状态、错误和概念类文章可删减无意义章节，但必须写清适用页面、所需权限和不能做什么。

## 事实边界

- 每篇文章必须至少绑定一个真实页面、路由、业务对象、状态、错误或菜单。
- 当前系统没有的能力必须写成“当前未实现”或“当前仅提供只读/占位/目录能力”，不能写成已支持。
- 不写真实客户、供应商、价格、单号、库存数量、银行账号、税号、财务金额或审批意见。
- 示例只能使用脱敏、虚构或通用占位表达。
- 权限说明使用角色或权限语义，不提供绕过权限、审批、校验或状态机的方法。
- 帮助内容对所有登录用户统一可见，文章内部说明需要的角色或权限。

## 关键词规则

每篇文章关键词至少覆盖以下三类：

- 页面入口：菜单名、页面名、路由语义，例如“采购订单、新建采购单”。
- 操作和字段：按钮名、字段名、模板列名、错误文案，例如“提交审批、供应商、税率、参数校验失败”。
- 常用口语：用户常问法，例如“为什么不能提交、下一步去哪、按钮没了、无法登录”。

## 未实现和部分支持写法

- 未实现能力：写“当前未实现，页面不提供入口，不能通过接口绕过页面执行”。
- 只读能力：写“当前仅用于查看，不产生业务写入”。
- 占位能力：写“当前页面为占位或入口说明，尚未提供完整业务操作”。
- 部分支持能力：写清已支持部分、未支持部分和用户应该停止的位置。

## 验收口径

- 搜索页面名、按钮名、状态名、字段名、错误文案和口语问题，应能定位到至少一篇明确文章。
- 文章答案不得把未实现能力写成可操作功能。
- 文章不得暗示 AI 助手、帮助中心或页面帮助会替用户执行新增、提交、审批、入库、出库、过账、结账等业务动作。
