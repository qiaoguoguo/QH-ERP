# 物料与 BOM 草稿导入模板兼容修复设计

## 目标

在不改变现有接口、权限、数据库、导入任务流程和业务校验的前提下，修复物料导入模板与 BOM 草稿导入模板的中文可读性和 Excel 下拉可用性，并保持旧英文模板继续可导入。

## 当前问题与根因

- 物料模板虽然已使用中文表头并写入中文枚举列表，但生成结果带有 `showDropDown="true"`。该 OpenXML 属性表示隐藏下拉箭头，因此用户看不到可选列表。
- 物料模板的“是否启用库存计价”和“是否启用项目成本”仍要求手填英文 `true/false`，没有中文“是/否”下拉。
- BOM 草稿模板的 `bom`、`items` 两个工作表仍直接展示英文表头，可读性不足。
- 解析端已有部分物料中英文兼容能力，但需要为新增中文布尔语义和 BOM 中文表头、中文枚举语义补齐兼容映射。

## 范围

本次仅处理：

- `/api/admin/import-templates/materials` 生成的 `materials-import-template.xlsx`。
- `/api/admin/import-templates/bom-drafts` 生成的 `bom-draft-import-template.xlsx`。
- 上述两个模板对应的上传解析兼容逻辑和受影响自动化测试。

明确排除：

- 历史数据导入适配器模板。
- 导出报表、打印模板、批量打印文件和普通附件。
- 页面布局、权限、数据库结构、业务状态机、审批、编码规则及导入确认流程。

## 模板设计

### 物料导入模板

- 保持现有 15 列顺序和字段含义不变。
- 单元格直接显示中文表头。
- “物料类型、来源类型、跟踪方式、状态、成本分类、库存计价类别”使用可见的中文下拉列表。
- “是否启用库存计价、是否启用项目成本”使用“是、否”中文下拉列表。
- 下拉验证覆盖数据行 `2-10001`，允许空值的规则保持现状，不改变后端必填校验。
- 保留冻结首行、筛选、表头批注和错误提示；统一表头样式、列宽和换行，确保中文表头完整可读。

### BOM 草稿导入模板

- 保持工作表名称 `bom` 和 `items` 不变，避免破坏既有解析入口。
- 保持两个工作表的字段顺序和字段含义不变。
- 两个工作表的表头改为中文直接展示，批注补充对应英文字段名，方便旧模板和接口字段对照。
- `bom` 工作表中的操作模式使用中文下拉选项；中文值在解析时归一化为既有内部模式值。
- 其他引用型字段继续填写系统编码，不将动态业务数据固化进模板下拉，避免模板生成依赖数据库实时状态。
- 两个工作表统一使用与物料模板一致的表头样式、合理列宽、冻结和筛选规则。

## 向后兼容

- 物料解析端继续接受全部旧英文表头，同时接受对应中文表头。
- 物料枚举继续接受英文枚举码，同时接受模板展示的中文枚举值。
- 物料布尔字段继续接受 `true/false`，新增接受“是/否”；大小写和首尾空白按现有标准化方式处理。
- BOM 解析端继续接受旧英文表头，并新增接受对应中文表头。
- BOM 操作模式继续接受旧英文值，并新增接受模板展示的中文值。
- 不改变字段顺序兜底、文件大小限制、行数限制、引用校验和错误码。

## 实现边界

- 优先复用现有 Apache POI 模板生成方法，以模板参数补充下拉和样式，不引入新依赖。
- 修复下拉可见性时只调整数据验证箭头抑制配置，不放宽数据验证错误阻止策略。
- 不重构文档任务服务、不抽象全系统模板框架、不修改其他模板。
- 已存在的工作树变更必须保留并在其基础上增量实现，不得回退用户已有修改。

## 测试与验收

- 测试先行验证物料模板中文表头、六类中文枚举下拉、两类“是/否”下拉以及下拉箭头可见。
- 测试先行验证 BOM 两个工作表名称不变、中文表头直接展示和操作模式中文下拉可见。
- 验证两个解析端分别接受新中文模板和旧英文模板。
- 验证中文枚举、中文布尔和中文操作模式能归一化为现有内部值。
- 只运行受影响后端测试和必要的前端下载入口回归；不扩大到无关业务模块。
- 重启本地 `5174` 环境后，从页面重新下载两个模板，检查表头、下拉和工作表结构。

## 完成条件

- 两个模板在 Excel 中可直接看到中文表头和应有的中文下拉箭头。
- 新中文模板可成功通过预检，旧英文模板仍可通过同一解析链路。
- 受影响自动化测试通过，页面下载入口可用。
- 修改文件和行为严格限制在本设计范围内。
