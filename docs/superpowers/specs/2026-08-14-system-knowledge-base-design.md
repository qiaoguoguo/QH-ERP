# 全系统操作知识库设计

## 文档状态

- 阶段：第一阶段，系统操作知识库建设。
- 当前状态：总体方向与简化原则已由用户确认，详细设计待最终确认。
- 后续阶段：只读 AI 助手；不属于本阶段。
- 本文件是本阶段唯一权威说明，实施、审查和验收均以本文件为准。

## 背景

现有 `docs/manual/system-operation-manual.md` 已覆盖部分模块名称和基础说明，但内容深度不足，不能完整回答实际使用中频繁出现的以下问题：

- 页面用于处理什么业务，应该从哪里进入。
- 字段、按钮、状态和错误提示分别代表什么。
- 当前状态为什么不能操作，下一步应去哪个页面。
- 某项操作会影响采购、销售、库存、生产、成本、财务或审批中的哪些数据。
- 不同角色需要什么权限，为什么菜单或按钮不可见。
- 一个完整业务流程的前置条件、操作顺序、异常处理和结束条件是什么。

后续只读 AI 助手如果直接依赖当前简略手册，将放大内容缺失和错误指引风险。因此必须先建设一套绑定当前系统真实页面和真实业务逻辑的完整知识库，并通过普通用户可直接使用的帮助中心完成内容验收。

## 已确认设计决策

- 第一阶段只建设知识库和系统帮助中心，不建设 AI 助手。
- 知识库是所有登录用户统一使用的一套内容，不按角色过滤文章。
- 文章应明确说明相关操作需要的角色或权限，但所有登录用户都能浏览这些说明。
- 超级管理员可以直接新增、编辑、启用、停用和删除知识条目。
- 保存后立即生效，不设置草稿、审核、发布审批或复杂版本流转。
- 仅记录创建人、创建时间、修改人和修改时间，并复用系统现有审计能力记录维护动作。
- 普通用户只能浏览和搜索，不能维护知识内容。
- 知识库模块以新增代码为主；对既有代码仅做菜单、路由、公共布局、权限注册和模块装配所需的最小接入修改。
- 不修改采购、销售、库存、生产、质量、成本、财务和审批等既有业务逻辑。

## 阶段目标

建立一套完整、准确、可维护、可浏览、可搜索、可追溯到当前系统真实功能的操作知识库，满足以下目标：

- 用户不依赖开发人员即可查询页面用途、操作步骤、字段含义和错误处理。
- 用户能够理解单据状态、审批状态和上下游业务影响。
- 用户可以按模块、页面名、按钮名、字段名、单据名、错误提示和常用口语搜索知识。
- 超级管理员能够用简单页面直接维护知识内容。
- 后续只读 AI 助手能够复用同一套启用状态的知识内容，不另建知识口径。

## 范围

### 知识内容

- 系统菜单、路由、列表、详情、表单、弹窗、抽屉和导入导出入口。
- 页面用途、入口路径、适用场景、前置条件和完整操作步骤。
- 关键字段、必填规则、格式限制、枚举含义、默认值和字段联动。
- 页面按钮的显示条件、禁用条件、业务作用和执行结果。
- 业务状态、审批状态、库存状态、到货状态、结案状态等状态含义。
- 采购、销售、库存、生产、质量、成本、财务和审批之间的上下游影响。
- 角色、权限和无权限时的页面表现说明。
- 常见校验错误、业务报错、导入失败和用户可执行的处理方式。
- 正常流程、异常流程、撤销、取消、关闭、结案和追溯路径。

### 系统能力

- 面向所有登录用户的只读帮助中心。
- 按模块分类浏览、关键词搜索、文章详情和关联知识查看。
- 当前业务页面到相关帮助内容的只读入口。
- 面向超级管理员的知识条目维护页面。
- 知识分类、文章、关键词、页面路径关联和启停状态维护。
- 只读查询接口和超级管理员维护接口。
- 初始知识内容导入和覆盖清单。

## 明确排除项

- AI 对话、模型接入、向量数据库、RAG 编排和外部数据传输方案。
- AI 代替用户新增、编辑、删除、提交、审批、过账、入库或执行任何业务操作。
- 调用或包装采购、销售、库存、生产、财务等业务写接口。
- 按角色过滤知识文章。
- 草稿、审核、发布审批、多级复核和复杂版本管理。
- 在线客服、工单、评论、点赞、反馈流转和阅读统计。
- 借知识库建设修改既有业务规则、状态机、审批规则、权限含义或数据口径。
- 对既有业务页面进行顺带重构或无关样式治理。

## 总体架构

知识库采用独立业务模块，分为内容存储、只读查询、超级管理员维护和用户帮助中心四部分：

1. 知识内容保存在独立知识库数据表中，不写入业务单据表。
2. 只读查询接口向所有已登录用户提供分类、搜索、详情和页面关联查询。
3. 维护接口只允许超级管理员调用，保存后立即对只读查询生效。
4. 帮助中心和后续 AI 助手读取同一套启用内容。
5. 当前页面帮助只传递页面路由或页面标识，不读取当前业务单据内容。

知识库不是通用 ERP 教程。每条内容必须能绑定当前系统中的模块、页面、业务对象、状态、错误或操作路径。

## 知识信息架构

### 一级领域

- 工作台与通用操作。
- 账号、角色、权限和系统管理。
- 基础资料、编码规则、计量单位、客户和供应商。
- 物料、物料分类、物料类型和 BOM。
- 库存、仓库、批次、序列号和库存追溯。
- 质量检验与质量状态。
- 采购请购、询价比价、价格协议、采购订单、入库和退货。
- 销售项目、报价、合同、销售订单、出库和退货。
- 计划、生产工单、领料、报工、完工入库和委外。
- 成本归集、成本计算和成本查询。
- 应收、应付、资金、凭证、期初、固定资产和财务结账。
- 经营报表、业务追溯和数据口径。
- 审批待办、消息、任务、历史导入和数据修复。
- 导入、导出、附件、审计和来源链。
- 状态、枚举、错误提示、术语和跨模块流程。

### 知识条目类型

- 页面操作：针对一个列表、详情、表单、弹窗或抽屉。
- 业务流程：针对跨页面、跨模块的完整流程。
- 字段解释：针对重要字段、枚举、默认值和联动规则。
- 状态解释：针对业务状态、审批状态和允许操作。
- 错误处理：针对报错文案、触发原因和处理方式。
- 权限说明：针对角色、菜单和操作权限。
- 导入导出：针对模板、字段、枚举、校验和失败处理。
- 业务概念：针对价格协议、有效采购供给、信用档案等概念。

## 单条知识内容标准

每条知识根据类型选用以下字段，不要求无业务意义的字段强制展示：

- 标题。
- 简短摘要。
- 所属模块和知识类型。
- 关联菜单路径、页面名称和路由。
- 适用角色或所需权限说明。
- 功能用途和适用场景。
- 操作前置条件。
- 完整页面操作步骤。
- 关键字段及填写规则。
- 按钮显示、禁用和执行条件。
- 状态变化及允许操作。
- 上游来源和下游影响。
- 常见错误、触发原因和处理方式。
- 关联知识条目。
- 搜索关键词和常用别名。
- 启用状态、排序、创建和更新时间。

内容必须使用当前系统中文页面语义，不以内部枚举码、接口名或代码类名替代用户能理解的业务描述。确需说明内部值时，应同时给出中文语义。

## 数据设计

### 知识分类

保存分类名称、上级分类、排序、启用状态和审计字段。分类最多支持必要的两级结构，避免形成难以维护的复杂目录树。

### 知识文章

保存标题、摘要、正文、分类、知识类型、关键词、关联路由、关联页面名称、适用角色或权限说明、排序、启用状态和审计字段。

正文采用受控富文本或 Markdown 存储，最终实现应优先复用项目已有编辑与展示能力，不为知识库引入重量级内容管理框架。

### 关联关系

文章之间只支持简单的相关知识关联。页面关联通过规范化路由或页面标识完成，不关联具体业务单据 ID，也不读取业务数据。

### 状态

仅使用“启用、停用”两种状态：

- 启用：普通用户搜索和浏览可见，后续 AI 助手可读取。
- 停用：普通用户和后续 AI 助手不可见，超级管理员仍可维护。

不增加草稿、待审核、已发布、已驳回等状态。

## 检索设计

- 支持按标题、摘要、正文、关键词、页面名称、菜单名称、按钮名称和错误文案搜索。
- 搜索结果优先级依次为标题、关键词、页面名称、摘要和正文命中。
- 支持常用中文别名，例如“请购单、采购申请”“价格协议、采购协议价”。
- 支持从当前路由查询关联帮助，但不采集表单数据、单号、金额或其他业务内容。
- 第一阶段不引入外部搜索引擎、向量数据库或语义模型。
- 知识规模较小时使用数据库只读检索，避免为简单需求增加额外基础设施。

## 页面设计

### 用户帮助中心

- 路由建议：`/help`。
- 所有登录用户可访问。
- 标题区显示“系统帮助中心”和用途说明。
- 提供突出的统一搜索框，但保持 ERP 工具型页面信息密度，不设计成营销首页。
- 左侧或顶部提供模块分类，主体显示搜索结果、常用流程和最近更新内容。
- 搜索结果展示标题、摘要、模块、知识类型和命中关键词。
- 空结果明确提示更换页面名、按钮名、字段名或报错文案搜索。

### 知识文章详情

- 路由建议：`/help/articles/:id`。
- 显示标题、摘要、所属模块、更新时间和正文。
- 页面操作类内容优先展示入口路径、前置条件、操作步骤、状态影响和常见错误。
- 提供目录锚点、关联知识和返回搜索结果的上下文。
- 页面中不提供任何业务执行按钮。

### 当前页面帮助入口

- 在公共布局的稳定位置提供“页面帮助”入口。
- 根据当前规范化路由查询关联文章。
- 无关联文章时进入帮助中心并自动带入当前页面名称作为搜索条件。
- 入口只负责导航，不触发当前页面任何业务动作。

### 知识管理列表

- 路由建议：`/system/knowledge`。
- 仅超级管理员可访问。
- 标题区右侧提供“新增知识”主按钮。
- 筛选区按页面规范使用标签置顶网格，支持关键词、分类、知识类型和启用状态。
- 表格显示标题、分类、类型、关联页面、状态、更新时间和操作。
- 操作列使用项目统一按钮样式，提供编辑、启用或停用、删除。
- 默认每页 10 条，支持 10、20、50、100 条切换。

### 知识编辑页面

- 仅超级管理员可访问。
- 包含标题、摘要、分类、知识类型、正文、关键词、关联路由、关联页面、角色或权限说明、排序和启用状态。
- 必填、错误、禁用和保存中状态必须清晰。
- 保存后立即生效，并返回列表或详情。
- 删除、停用等高风险操作使用项目统一确认弹窗。

## 页面规范映射

本阶段新增页面必须遵守 `docs/ui/page-standards.md`，重点验收：

- 工作台左侧导航、顶部账号区和主内容滚动模型保持不变。
- 页面标题、说明和页面级主操作位置统一。
- 管理列表筛选采用标签置顶网格。
- 管理表格位于横向滚动容器，操作列可访问，分页规则统一。
- 搜索空态、加载态、错误态和无结果状态清晰。
- 编辑表单必填、错误、禁用和保存中状态可识别。
- 文章详情和跨页面帮助入口保留返回上下文。
- 删除、停用使用统一确认弹窗，不使用浏览器原生确认框。
- 页面开发考虑响应式，但本阶段测试和验收只覆盖真实桌面浏览器。

本阶段不申请页面规范例外。

## 接口边界

### 普通用户只读接口

- 查询启用分类。
- 分页搜索启用文章。
- 查询启用文章详情。
- 按当前页面路由查询关联文章。
- 查询相关文章。

这些接口要求已登录，但不按业务角色过滤内容，不返回停用文章，不读取业务单据数据。

### 超级管理员维护接口

- 分类新增、修改、排序、启停和删除。
- 文章新增、修改、启停和删除。
- 超级管理员可查询全部状态文章。

所有维护接口必须复用现有认证、超级管理员授权、参数校验、错误响应和审计机制。知识库接口不得调用任何业务写服务。

## 权限和安全边界

- 所有登录用户统一浏览启用知识内容。
- 未登录用户不能访问帮助中心和知识接口。
- 只有超级管理员可以维护分类和文章。
- 文章中可以说明某项操作需要的角色或权限，但不隐藏该文章。
- 知识正文不得固化真实客户、供应商、价格、库存、单号、财务金额或审批意见。
- 示例统一使用脱敏或虚构数据。
- 文章不得提供绕过权限、校验、审批或业务规则的方法。
- 当前页面帮助不上传当前页面表单值和业务数据。

## 初始知识建设方法

1. 以真实菜单和路由形成页面覆盖清单。
2. 以真实页面字段、按钮、空态、错误态和操作路径形成页面条目。
3. 以后端校验、状态机、枚举和错误语义补齐业务规则。
4. 以现有操作手册、阶段说明和验收结论补充历史业务解释，但与真实系统冲突时以当前实现为准并记录差异。
5. 按采购、销售、库存、生产、成本、财务和审批等主链路补充跨模块流程。
6. 使用页面名、按钮名、字段名、状态名、报错文案和用户口语建立关键词与别名。
7. 用真实使用问题构建验收题集，逐条验证可检索性和回答依据。

不得仅根据通用 ERP 经验编写当前系统不存在的功能。

## 错误处理

- 搜索参数非法时返回明确参数错误，不返回空白页面。
- 文章不存在或已停用时返回统一“知识内容不存在或已停用”提示。
- 分类下仍有文章时不允许直接删除分类，提示先迁移或删除文章。
- 关联文章失效时不影响主文章读取，只忽略无效关联并记录维护提示。
- 超级管理员保存失败时保留已输入内容并展示可见错误。
- 帮助中心不可用不得影响采购、销售、库存等业务页面本身的使用。

## 修改边界

### 以新增为主

- 新增独立知识库后端模块、数据表、迁移、接口和测试。
- 新增帮助中心、文章详情、知识管理列表和编辑页面。
- 新增初始知识内容、覆盖清单和验收题集。

### 既有代码最小接入

- 菜单和路由注册。
- 公共布局中的页面帮助入口。
- 后端模块装配、权限注册和数据库迁移注册。
- 必要的统一错误、审计和公共组件复用。

### 禁止改动

- 既有业务状态机、审批规则、权限含义和数据口径。
- 采购、销售、库存、生产、质量、成本和财务业务接口行为。
- 无关页面布局、样式和组件。
- 无关数据库表和历史业务数据。

## 工作包

### 知识规范与覆盖清单

- 冻结知识分类、条目模板、关键词规则和覆盖口径。
- 建立全部现有菜单、页面、流程、状态和错误的覆盖清单。
- 形成初始验收题集。

### 后端知识库能力

- 实现独立数据模型、迁移、只读查询和超级管理员维护能力。
- 实现简单检索、页面关联、认证、授权、校验和审计。
- 不接入业务写服务。

### 前端帮助中心与管理页面

- 实现帮助中心、文章详情、当前页面帮助入口、管理列表和编辑页面。
- 严格遵循页面规范和项目统一组件样式。

### 全量知识内容建设

- 按覆盖清单编写并录入现有系统全部操作知识。
- 核对真实页面、权限、状态机、字段校验、错误和跨模块影响。
- 不把未实现能力写成已支持功能。

### 验收与覆盖核对

- 验证页面、流程、状态、字段、权限、错误和跨模块知识覆盖。
- 验证搜索关键词、别名、页面关联和统一用户可见性。
- 在真实桌面浏览器验收新增页面的功能与页面规范。

## 验收矩阵

| 验收维度 | 完成标准 |
|---|---|
| 菜单覆盖 | 所有现有一级、二级菜单均有知识条目或明确的不适用说明 |
| 页面覆盖 | 已上线列表、详情、表单、关键弹窗、抽屉、导入导出入口均可查询 |
| 操作覆盖 | 新增、编辑、删除、提交、审批、确认、关闭、取消、导入、导出和追溯均有说明 |
| 字段覆盖 | 关键表单和模板的必填、格式、枚举、默认值及错误处理可查 |
| 状态覆盖 | 核心业务对象的状态含义、允许动作、禁止原因和下一步影响可查 |
| 流程覆盖 | 采购、销售、库存、生产、成本、财务和审批核心链路有端到端说明 |
| 权限说明 | 涉及权限的文章说明所需角色或权限及无权限页面表现 |
| 错误覆盖 | 高频校验、业务异常、审批异常和导入失败能按错误文案检索并获得处理方式 |
| 检索能力 | 页面名、菜单名、按钮名、字段名、状态名、单据名、错误文案和常用口语均能命中相关内容 |
| 页面关联 | 从当前页面可进入关联帮助；无关联时可进入带页面关键词的帮助中心搜索 |
| 统一可见 | 任一已登录用户可浏览全部启用文章，不按角色过滤 |
| 维护边界 | 只有超级管理员可直接维护；保存后立即生效；普通用户只读 |
| 数据安全 | 不包含真实业务数据，不读取业务单据，不调用业务写接口 |
| 页面规范 | 新增页面逐项满足 `docs/ui/page-standards.md` 的适用要求 |
| AI 准备度 | 后续助手可读取同一套启用内容，且每条回答依据可定位到知识文章 |

## 完成条件

- 帮助中心、文章详情、页面帮助入口和知识管理页面可在本地系统访问。
- 超级管理员可以直接维护知识，普通用户统一浏览启用内容。
- 初始知识覆盖清单和验收题集中的必需项全部闭合。
- 用户提出的典型系统操作问题可以通过搜索定位到明确、准确的知识内容。
- 新增页面完成真实桌面浏览器功能和页面规范检验。
- 知识库故障不影响既有业务模块。
- 修改范围严格限定在独立知识库模块和必要接入点。
