# 系统代码逻辑知识层设计

## 目标

为后续 AI 操作助手建立可追溯的系统逻辑知识来源，使回答不只依赖人工知识库，还能引用当前版本代码中的页面、接口、权限、校验、状态和错误处理事实。

## 本阶段边界

- 只新增离线证据抽取、版本化索引、后端导入校验和内部只读检索能力。
- 不新增 AI 问答页面，不接入模型，不开放新的前端接口。
- 不读取生产数据、日志、环境变量、凭据或上传附件。
- 不修改业务状态机、审批、库存、财务、权限或现有知识库内容。
- 索引导入失败不得阻止 ERP 启动；后续助手应退化为只使用人工知识库。

## 证据来源

构建器只扫描以下白名单：

- 前端路由、菜单、业务模块和页面路由清单测试。
- 后端系统业务包、错误码、权限授权管理器和数据库迁移。
- 后端系统业务测试。

抽取类型包括：路由、菜单、页面元素、接口、校验、权限、枚举、状态流转、错误、数据库约束和测试行为。

## 数据流

1. 构建脚本读取白名单源码，清洗文本并生成结构化证据。
2. 每个源文件和每条证据计算 SHA-256，形成版本化 JSON 索引。
3. 后端启动时校验索引结构、来源路径和摘要，再以事务导入 V42 快照表。
4. 任一时刻只激活一个完整快照；相同摘要重复启动不会重复写入。
5. 内部混合检索器合并人工知识文章摘要与代码逻辑证据，供后续 AI 服务使用。

## 安全与可信度

- 不扫描配置目录、构建产物、依赖目录、日志和用户上传目录。
- 证据仅保留短摘要、符号、来源文件和行号，不保存完整源码。
- 敏感赋值在生成时脱敏，后端再次拒绝明显凭据内容和越界路径。
- 所有证据都携带来源摘要、证据摘要和可信度；无法找到依据时不得推测业务结论。
- 本阶段的代码证据无控制器，不能直接由浏览器读取。

## 后续问答原则

后续 AI 回答时应优先组合人工知识库的操作语言与代码证据的真实约束。两者冲突时，明确提示版本或内容可能过期，并以当前激活代码快照作为系统行为依据；涉及用户实际业务数据时只给查询路径，不代替用户操作。
